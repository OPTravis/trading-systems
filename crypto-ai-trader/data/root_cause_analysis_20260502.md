## 二、各異常根因分析

### 2.1 Kanban Worker 崩潰 — 配置問題

**現象**: 多個 worker 進程報 "pid not alive" 錯誤

**根本原因**:
- WSL 環境下進程管理存在已知限制
- 多個 kanban worker 同時運行可能導致資源競爭（記憶體/交換空間）
- 這是基礎設施問題，與交易系統邏輯無關

**分類依據**: 屬於「配置問題」而非交易系統問題，因為：
- Binance API 連接正常
- 無 API 429/418 限流錯誤
- 僅影響 worker 進程，不影響交易執行

**建議**: 增加 worker 資源限制或減少並發數

---

### 2.2 PENDLEUSDT TP 觸及 — 正常運行（非異常）

**現象**: TP 目標 $1.533，現價 $1.533（距 0.02%）

**根本原因**: 
- 這是正常的交易行為，價格達到 TP 目標
- 限價賣單應已成交或即將成交

**分類依據**: 屬於「正常運行」而非異常，因為：
- 系統 SL 保護機制正常運作
- 無訂單失敗記錄

**結論**: 此項不構成異常，系統正常運作

---

### 2.3 AVAXUSDT TP 缺失 — 配置問題

**現象**: 倉位價值 $5.19，僅有 SL 保護，無 TP

**根本原因**:
- 倉位價值 $5.19 低於 minNotional 拆分門檻（Binance 最低訂單金額）
- 系統無法同時掛 TP+SL，因此採用 SL-only 保護

**分類依據**: 屬於「配置問題」，因為：
- 這是 minNotional 限制導致的系統行為
- 非 API 問題（API 連接正常）
- 非邏輯錯誤（系統已自動處理）
- 非市場條件異常

**建議**: 
- 考慮自動合併或清理低於 minNotional 的倉位
- 或在倉位管理中增加 minNotional 檢查邏輯

---

### 2.4 網格交易停止 (SOL/BTC) — 邏輯錯誤

**現象**:
- SOLUSDT: 狀態 `stopped`，0 筆交易，0 PnL
- BTCUSDT: 狀態 `initialized`，從未啟動

**根本原因分析**:

#### SOLUSDT（已啟動但停止）
- 啟動時間: 2026-04-28 14:14:52
- 最後檢查: 2026-04-28 14:14:52（與啟動時間相同）
- 交易數: 0
- 可能原因:
  1. 啟動後立即停止（可能是訂單下單失敗）
  2. 網格範圍設置不合理（當前 SOL 價格可能已超出網格範圍）
  3. 資金不足無法下單

#### BTCUSDT（從未啟動）
- 狀態: `initialized`
- 最後檢查: 2026-04-24 15:36:24
- 交易數: 0
- 可能原因:
  1. 用戶未執行 start 命令
  2. 網格參數配置問題（如 capital_per_grid < minNotional）

**分類依據**: 屬於「邏輯錯誤」，因為：
- 網格交易系統應能自動處理範圍外價格
- SOL 已啟動但立即停止，可能是訂單執行邏輯問題
- BTC 從未啟動，可能是初始化後的啟動流程問題

**建議**:
- 檢查 SOL 網格停止的具體原因（查看日誌）
- 檢查 BTC 網格為何從未啟動
- 確認網格範圍是否仍適合當前市場價格
