### 2.3 数量精度处理（stepSize floor）— ⚠️ 部分正确，存在不一致

#### ✅ binance_client.py 中的 floor 逻辑（正确）
- `place_order()` 第 447-453 行：
  ```python
  import math
  step = 10 ** (-qty_decimals)
  floored = math.floor(quantity / step) * step
  params["quantity"] = f"{floored:.{qty_decimals}f}"
  ```
- **优点**: 使用 `math.floor` 确保不会向上取整导致超出可用余额，注释明确说明了这一点。

#### ⚠️ grid_trader.py 中的精度处理（有问题）
- `_round_qty()` 第 842-843 行：
  ```python
  def _round_qty(self, qty: float, decimals: int) -> float:
      return round(qty, decimals)
  ```
- **问题**: 使用 `round()` 而非 `math.floor()`。`round()` 可能向上取整（例如 0.00028958 → 0.00029），导致卖出数量超过实际持仓，触发 Binance "insufficient balance" 错误。
- **风险**: 高频网格交易中，精度向上取整会导致订单失败率增加。

#### ✅ smart_order.py 中的 floor 逻辑（正确）
- `apply_qty_precision()` 第 97-115 行：
  ```python
  qty = (qty // step_size) * step_size
  qty = round(qty, qty_decimals)
  ```
- 使用整数除法 `//` 实现 floor 效果，逻辑正确。

### 2.5 下单失败时的回退逻辑 — ✅ 已实现

#### ⚠️ grid_trader.py
- `start()` 和 `tick()` 中没有显式检查 USDT 可用余额是否足够。

### 2.7 重复下单保护 — ❌ 缺失

#### ❌ 严重缺失
- **binance_client.py**: `place_order()` 没有设置 `newClientOrderId`。
- **smart_order.py**: `place_buy_with_sl_tp()` 没有设置 `newClientOrderId`。
- **grid_trader.py**: `start()` 和 `tick()` 中没有幂等性保护。

#### 风险分析
- **网络超时重试场景**: 如果第一次请求实际上已到达 Binance 并成交，但网络超时导致客户端认为失败，客户端可能再次调用 `place_order()`，导致重复下单。
- **Binance 幂等性机制**: Binance API 支持 `newClientOrderId` 字段，相同 ID 的重复请求会被拒绝（返回 "Duplicate order sent"）。当前代码完全没有使用此机制。

#### 建议修复
在所有下单函数中增加 `newClientOrderId`：
```python
import uuid
params["newClientOrderId"] = f"bot_{symbol}_{side}_{uuid.uuid4().hex[:16]}"
```
对于需要重试的场景，应使用相同的 `newClientOrderId`，这样 Binance 会自动去重。

## 3. 其他发现

### 3.1 STOP_LOSS 订单类型问题 — ⚠️
- `place_stop_loss_market()` 第 502-507 行使用 `"STOP_LOSS"` 类型。
- **注意**: Binance SPOT API 中，`STOP_LOSS` 类型实际上是 `stopPrice` 触发的市价单。但 SPOT 账户可能不支持纯 `STOP_LOSS`，需要使用 `STOP_LOSS_LIMIT` 或 OCO。
- **建议**: 确认 Binance SPOT 是否支持 `STOP_LOSS`（非 LIMIT）。如果不支持，应改为 `STOP_LOSS_LIMIT`。

### 3.2 smart_order.py 中的变量引用错误 — ❌
- `place_buy_with_sl_tp()` 第 330-338 行：
  ```python
  tp1_qty = self.apply_qty_precision(filled_qty * (sl_tp['tp1_size_pct'] / 100), filters)
  ```
- **问题**: `filters` 变量未在此函数作用域内定义。函数内只有 `full_symbol`、`price`、`positions`、`quantity`、`usdt_amount`、`sl_tp` 等变量。
- **后果**: 运行时抛出 `NameError: name 'filters' is not defined`，导致 SL/TP 订单全部失败。
- **修复**: 应在函数开头调用 `self.get_symbol_filters(full_symbol)` 并赋值给 `filters`。

### 3.3 grid_trader.py 的 _verify_fill 直接访问内部 client — ⚠️
- 第 514 行: `order = self.client.client.get_order(...)`
- **问题**: 直接访问 `self.client.client`（内部 SDK 对象），破坏了封装。如果更换交易所客户端会失败。
- **建议**: 应使用 `self.client.get_order(symbol, order_id)`，该方法已在 `binance_client.py` 第 753 行实现。

### 3.4 精度解析潜在 bug — ⚠️
- `get_price_precision()` 第 397-408 行和多处使用：
  ```python
  price_decimals = len(f['tickSize'].rstrip('0').split('.')[-1])
  ```
- **问题**: 如果 `tickSize` 是 `"1.00000000"`，`rstrip('0')` 后变为 `"1."`，`split('.')[-1]` 为空字符串，`len('')` = 0。这会导致精度为 0，对于整数价格的币种（如某些低价币）是正确的，但对于 `"0.01000000"` 会正确得到 2。
- **更安全的写法**: 使用 `Decimal` 解析 stepSize，避免字符串操作风险。
